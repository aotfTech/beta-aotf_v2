# UI Components & Dependencies

AOTF uses a rich UI stack built on top of Next.js with a combination of component libraries, animation tools, and utility packages.

## Core Component Libraries

### Aceternity UI

For premium animated components (hero sections, spotlight effects, floating elements):

```json
"@aceternity/ui": "^1.x"
```

Custom Aceternity components are in `components/aceternity/`.

### React Bits

For additional interactive UI elements and micro-interactions:

```json
"react-bits": "^x.x"
```

## Animation Libraries

### Framer Motion

Used for page transitions, modal animations, and component enter/exit animations:

```json
"framer-motion": "^12.x"
```

### GSAP (GreenSock Animation Platform)

Used for complex scroll-triggered animations on the landing page and admin dashboard:

```json
"gsap": "^3.x"
```

### Lottie React

Used for micro-animation JSON files (loading states, success indicators):

```json
"lottie-react": "^2.x"
```

## Data Fetching

AOTF uses native `fetch`, React state/hooks, and server actions where appropriate. Server-side data is fetched in Server Components or route handlers; client components call the `/api` routes directly.

## Admin-Specific UI

The admin panel (`/admin/*`) uses a custom layout with:

- `react-dnd` — Drag-and-drop interactions in admin workflows
- `@tiptap/react` — Rich text notes and content editing
- HeroUI and Radix primitives — Accessible controls, dialogs, tables, forms, and overlays

## Custom Component Directory

```
components/
├── aceternity/      # Aceternity UI customized components
├── admin/           # Admin-specific components
├── docs/            # Documentation components (DocToolbar, etc.)
├── mdx/             # MDX custom element renderers
├── providers/       # Context providers (HeroUI, theme, etc.)
├── shared/          # Shared components used across both admin and user UIs
├── skeletons/       # Route loading placeholders (FeedSkeleton, etc.)
└── ui/              # Base UI components (Button wrappers, etc.)
```

## Loading Skeletons

AOTF uses Next.js App Router [`loading.tsx`](https://nextjs.org/docs/app/api-reference/file-conventions/loading) files with shared skeleton components in `components/skeletons/`:

| Component | Used by |
|---|---|
| `FeedSkeleton` | `/posts`, `/jobs` list pages |
| `DetailSkeleton` | `/posts/[id]`, `/jobs/[id]` detail pages |
| `ProfileSkeleton` | `/u/[username]` public profiles |
| `AdminPageSkeleton` | `/admin`, `/admin/invoices` |

Import from `@/components/skeletons` (barrel export in `components/skeletons/index.ts`).

**Convention**: Prefer these shared skeletons over inline loaders in new routes. `AdminDashboardSkeleton` is exported but the dashboard page uses a local inline skeleton instead.

Skeleton components set `aria-busy` and `aria-label` for accessibility during Suspense boundaries.
